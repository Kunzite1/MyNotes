# 任务创建过程

概要：任务创建暴露给用户的入口是`xTaskCreate`，下面会讲述`xTaskCreate`的流程，和内部使用的关键函数/宏的作用、流程。

## xTaskCreate()

当调用`xTaskCreate`时，首先会根据栈增长方向（从低地址到高地址还是从高到低）选用不同的顺序为**任务栈**和**TCB（任务控制块）**分配空间。

判断TCB创建成功后，调用`prvInitialiseNewTask`初始化任务，然后调用`prvAddNewTaskToReadyList`将任务添加到就绪链表。

之后将`xReturn`复制为pdPASS并返回，表明任务创建完毕。

## prvInitialiseNewTask()

首先依旧根据栈地址增长方向，计算栈顶地址，然后将任务名传入TCB。

用#if等宏，处理好：任务优先级上限限定、任务在互斥量中的base优先级。

调用`vListInitialiseItem`初始化任务的**状态组件**、**事件组件**。

通过宏`listSET_LIST_ITEM_OWNER`，让调度器/队列/事件组等组件能反查到所属TCB，即设置其`pxOwner`。

初始化任务栈，使任务看起来像已经在运行中，只是被中断了，这样后续PendSV只要做一次普通的寄存器恢复，就能“回到”任务入口。

其余过于细节的守卫宏，暂不讨论。

## prvAddNewTaskToReadyList ()

此任务开头就调用宏`taskENTER_CRITICAL`关闭中断，防止中断打断链表更新工作。

如果新任务是首个任务，则调用`prvInitialiseTaskLists`初始化任务相关链表。

如果调度器未运行，且新任务比当前任务优先级高，则直接把参数任务作为当前任务。如果调度器正运行，且新任务比当前任务优先级高，则调用宏触发PendSV，请求将当前任务切换为新任务。**（当前任务指的是当前正在运行的任务）**

将新任务的TCB放进任务就绪链表。

## prvInitialiseTaskLists()

简要来说，这个函数会初始化各种任务链表，以下讲解有哪些

首先初始化每个优先级的链表，每个优先级都有一个链表。

初始化`xTasksWaitingTermination`，此链表存放等待被终止的任务。

初始化两个延迟任务链表`xDelayedTaskList1`、`xDelayedTaskList2`,并把 `pxDelayedTaskList`指向`xDelayedTaskList1`、`pxOverflowDelayedTaskList`指向`xDelayedTaskList2`。这是 FreeRTOS 处理 tick 计数溢出的双缓冲机制：xTickCount 接近 portMAX_DELAY 时调换两个指针，保证延迟比较不会因为wrap-around出错

初始化`xSuspendedTaskList`，用于存放被挂起的任务。

# 调度器启动过程

概要：暴露给用户的入口是`vTaskStartScheduler`。调用后，调度器先创建空闲任务（顺带触发所有任务链表的一次性初始化），再关闭中断、标记调度器运行，最后交给硬件层配置 SysTick/PendSV，通过一次 SVC 软中断"伪装的异常返回"无缝切入第一个任务。

## vTaskStartScheduler()

首先通过`xTaskCreate`创建空闲任务`prvIdleTask`（优先级`tskIDLE_PRIORITY`，即 0）。这是全局第一个任务，因此在`prvAddNewTaskToReadyList`内部会触发`prvInitialiseTaskLists`，一次性初始化所有任务链表。

由于本工程`configUSE_TIMERS`为0，跳过软件定时器任务的创建。

然后`portDISABLE_INTERRUPTS`关闭所有中断，避免调度器正式运行前被 tick 等中断打断。之后置`xSchedulerRunning = pdTRUE`、`xTickCount = 0`、`xNextTaskUnblockTime = portMAX_DELAY`。

最后调用`xPortStartScheduler()`。这个函数在正常运行时不会返回——控制权从此交给调度器。

## prvInitialiseTaskLists()

（由第一个任务的创建触发，而非 vTaskStartScheduler 直接调用）

为每个优先级（0~configMAX_PRIORITIES-1，即0~31）初始化一条就绪链表`pxReadyTasksLists[uxPriority]`。

初始化两条延时链表`xDelayedTaskList1/2`，并将`pxDelayedTaskList`/`pxOverflowDelayedTaskList`分别指向它们——这是处理 tick 计数溢出的双缓冲机制。

初始化`xPendingReadyList`（调度器挂起期间被解除阻塞的任务先放这里）、`xTasksWaitingTermination`（等待回收的任务）、`xSuspendedTaskList`（被挂起的任务）。

## xPortStartScheduler()

先把 PendSV 与 SysTick 设为最低中断优先级（`portNVIC_SYSPRI2_REG |= portNVIC_PENDSV_PRI / portNVIC_SYSTICK_PRI`），保证上下文切换和 tick 不会抢占更紧要的中断。

调用`vPortSetupTimerInterrupt()`配置 SysTick，产生 1ms 一个 tick 的中断。

清零`uxCriticalNesting`，然后调用`prvStartFirstTask()`启动第一个任务。

## prvStartFirstTask() 与 vPortSVCHandler()

`prvStartFirstTask`（汇编）：从向量表读出 MSP 初值并复位栈指针，开全局中断（`cpsie i/f`），然后执行`svc 0`触发 SVC 软中断。

`vPortSVCHandler`（汇编）：取`pxCurrentTCB->pxTopOfStack`（任务栈顶），把 r4~r11 弹出、恢复 PSP，`msr basepri, r0`（r0=0）放开中断，再通过`bx r14`"返回"。

关键：任务栈在创建时就被`pxPortInitialiseStack`预装成"刚被中断自动压栈"的样子（xPSR/PC/LR/R12/R3-R0 的伪栈帧）。所以 SVC 处理器最后这一次"异常返回"，硬件会自动从 PSP 弹出整个栈帧，CPU 便直接跳到任务入口函数——仿佛这个任务早已在运行、只是被中断打断了一次。

## 小结

"无缝切入第一个任务"的秘诀 = 创建时模拟中断压栈（pxPortInitialiseStack）+ 启动时一次真实异常返回（SVC → bx r14）。这之后再发生调度，就是 PendSV 的常规上下文切换了。
