# FreeRTOS 数据结构定义

> 整理范围：本工程 FreeRTOS V9.0.0。结构体中的条件成员会随 `FreeRTOSConfig.h` 和移植层宏变化；`Static..._t` 是为静态分配预留的等尺寸占位类型，应用不应依赖其内部字段。

## 1. 基础类型与句柄

### 1.1 移植层基础类型

在本工程 Cortex-M3 端口中，核心类型由 `portmacro.h` 定义：

| 类型 | 含义 |
| --- | --- |
| `StackType_t` | 一个任务栈元素的类型，Cortex-M3 上为 32 位 |
| `BaseType_t` | 架构自然宽度的有符号整数，用于返回值和布尔值 |
| `UBaseType_t` | 架构自然宽度的无符号整数，用于计数和优先级 |
| `TickType_t` | Tick 计数类型；本工程 `configUSE_16_BIT_TICKS == 0`，因此为 32 位 |
| `TaskFunction_t` | `typedef void (*TaskFunction_t)(void *)`，任务入口函数类型 |

### 1.2 不透明句柄

```c
typedef void * TaskHandle_t;
typedef void * QueueHandle_t;
typedef void * QueueSetHandle_t;
typedef void * QueueSetMemberHandle_t;
typedef QueueHandle_t SemaphoreHandle_t;
typedef void * EventGroupHandle_t;
typedef void * TimerHandle_t;
typedef void * CoRoutineHandle_t;
```

句柄在 API 层隐藏内部实现。实际分别指向 `TCB_t`、`Queue_t`、`EventGroup_t`、`Timer_t` 或 `CRCB_t`。应用只能通过 API 使用，不应强制转换后访问内部成员。

### 1.3 回调函数类型

```c
typedef BaseType_t (*TaskHookFunction_t)(void *);
typedef void (*TimerCallbackFunction_t)(TimerHandle_t xTimer);
typedef void (*PendedFunction_t)(void *pvParameter1, uint32_t ulParameter2);
typedef void (*crCOROUTINE_CODE)(CoRoutineHandle_t, UBaseType_t);
```

## 2. 链表结构（`list.h`）

FreeRTOS 内核所有就绪、延时和事件等待关系都建立在双向循环链表上。

### 2.1 `ListItem_t`：完整节点

```c
typedef struct xLIST_ITEM
{
    TickType_t xItemValue;
    struct xLIST_ITEM *pxNext;
    struct xLIST_ITEM *pxPrevious;
    void *pvOwner;
    void *pvContainer;
} ListItem_t;
```

| 成员 | 含义 |
| --- | --- |
| `xItemValue` | 排序键；状态链表中常保存唤醒 Tick，事件链表中常保存反转后的优先级 |
| `pxNext` / `pxPrevious` | 前后节点，组成双向循环链表 |
| `pvOwner` | 拥有此节点的对象，任务链表中通常指向 `TCB_t` |
| `pvContainer` | 当前所属 `List_t`；为 `NULL` 表示未插入链表 |

若 `configUSE_LIST_DATA_INTEGRITY_CHECK_BYTES == 1`，结构首尾还会插入完整性检查字段。

### 2.2 `MiniListItem_t`：尾部哨兵

```c
typedef struct xMINI_LIST_ITEM
{
    TickType_t xItemValue;
    ListItem_t *pxNext;
    ListItem_t *pxPrevious;
} MiniListItem_t;
```

它是删去 `pvOwner`、`pvContainer` 的精简节点，只作为链表尾部标记。`xItemValue` 初始化为 `portMAX_DELAY`，保证按值插入时始终位于末尾。

### 2.3 `List_t`：链表头

```c
typedef struct xLIST
{
    UBaseType_t uxNumberOfItems;
    ListItem_t *pxIndex;
    MiniListItem_t xListEnd;
} List_t;
```

| 成员 | 含义 |
| --- | --- |
| `uxNumberOfItems` | 有效节点数量，不含哨兵 |
| `pxIndex` | 遍历游标，支持同优先级任务轮转 |
| `xListEnd` | 永远存在的尾部哨兵，同时连接首尾节点 |

## 3. 任务相关结构（`task.h`、`tasks.c`）

### 3.1 `TCB_t`：任务控制块

```c
typedef struct tskTaskControlBlock
{
    volatile StackType_t *pxTopOfStack;
    ListItem_t xStateListItem;
    ListItem_t xEventListItem;
    UBaseType_t uxPriority;
    StackType_t *pxStack;
    char pcTaskName[configMAX_TASK_NAME_LEN];
    /* 以下还有由配置决定的可选成员 */
} tskTCB;

typedef tskTCB TCB_t;
```

| 成员 | 含义 |
| --- | --- |
| `pxTopOfStack` | 当前任务栈顶；必须是首成员，PendSV 汇编直接依赖此布局 |
| `xMPUSettings` | MPU 区域设置；仅 MPU 端口存在且必须是第二成员 |
| `xStateListItem` | 将任务挂入就绪、延时、挂起或待删除链表 |
| `xEventListItem` | 将同一任务同时挂入队列/信号量/事件组的等待链表 |
| `uxPriority` | 当前有效优先级 |
| `pxStack` | 任务栈内存起始地址，用于栈检查和释放 |
| `pcTaskName` | 固定长度调试名称 |
| `pxEndOfStack` | 向高地址增长的栈端口用于记录栈末端 |
| `uxCriticalNesting` | 某些端口把临界区嵌套深度保存在 TCB 中 |
| `uxTCBNumber` / `uxTaskNumber` | 跟踪与调试编号 |
| `uxBasePriority` | 未发生优先级继承时的基础优先级 |
| `uxMutexesHeld` | 当前持有互斥量数量 |
| `pxTaskTag` | 应用任务钩子 |
| `pvThreadLocalStoragePointers[]` | 线程本地存储指针数组 |
| `ulRunTimeCounter` | 累计运行时间计数 |
| `xNewLib_reent` | 每任务 Newlib 可重入上下文 |
| `ulNotifiedValue` | 32 位任务通知值 |
| `ucNotifyState` | 通知状态：未等待、正在等待或已有待处理通知 |
| `ucStaticallyAllocated` | 标记 TCB/栈的静态与动态来源，删除时决定是否释放 |
| `ucDelayAborted` | 标记阻塞是否被 `xTaskAbortDelay()` 中止 |

一个任务可同时出现在一个“状态链表”和一个“事件链表”中，因此 TCB 内含两个独立节点。例如等待队列数据时，`xStateListItem` 在延时链表中负责超时，`xEventListItem` 在队列接收等待链表中负责事件唤醒。

### 3.2 `eTaskState`：任务状态

```c
typedef enum
{
    eRunning = 0,
    eReady,
    eBlocked,
    eSuspended,
    eDeleted,
    eInvalid
} eTaskState;
```

`eBlocked` 表示等待时间或事件；`eSuspended` 表示显式挂起，也可能表示使用无限超时而进入挂起链表；`eDeleted` 表示已删除但 TCB 尚未被空闲任务回收。

### 3.3 `eNotifyAction`：通知更新动作

```c
typedef enum
{
    eNoAction = 0,
    eSetBits,
    eIncrement,
    eSetValueWithOverwrite,
    eSetValueWithoutOverwrite
} eNotifyAction;
```

分别表示只通知不改值、按位或、加一、无条件写值、仅在旧通知已处理时写值。

### 3.4 `TimeOut_t`：超时快照

```c
typedef struct xTIME_OUT
{
    BaseType_t xOverflowCount;
    TickType_t xTimeOnEntering;
} TimeOut_t;
```

同时记录进入等待时的 Tick 和 Tick 溢出次数，使队列等阻塞 API 能正确处理计数器回绕。

### 3.5 `TaskStatus_t`：任务状态快照

```c
typedef struct xTASK_STATUS
{
    TaskHandle_t xHandle;
    const char *pcTaskName;
    UBaseType_t xTaskNumber;
    eTaskState eCurrentState;
    UBaseType_t uxCurrentPriority;
    UBaseType_t uxBasePriority;
    uint32_t ulRunTimeCounter;
    StackType_t *pxStackBase;
    uint16_t usStackHighWaterMark;
} TaskStatus_t;
```

用于 `vTaskGetInfo()` 和 `uxTaskGetSystemState()`。它只是采样时刻的快照；返回后任务可能已经切换状态，`pcTaskName` 在任务删除后也可能失效。

### 3.6 MPU 任务结构

```c
typedef struct xMEMORY_REGION
{
    void *pvBaseAddress;
    uint32_t ulLengthInBytes;
    uint32_t ulParameters;
} MemoryRegion_t;

typedef struct xTASK_PARAMETERS
{
    TaskFunction_t pvTaskCode;
    const char * const pcName;
    uint16_t usStackDepth;
    void *pvParameters;
    UBaseType_t uxPriority;
    StackType_t *puxStackBuffer;
    MemoryRegion_t xRegions[portNUM_CONFIGURABLE_REGIONS];
} TaskParameters_t;
```

`MemoryRegion_t` 描述一个任务可访问的 MPU 区域；`TaskParameters_t` 汇总创建受限任务所需的入口、栈、优先级和区域表。

### 3.7 `eSleepModeStatus`

```c
typedef enum
{
    eAbortSleep = 0,
    eStandardSleep,
    eNoTasksWaitingTimeout
} eSleepModeStatus;
```

供 Tickless Idle 判断：放弃睡眠、按预计空闲时间睡眠，或在没有任务等待超时时仅由外部中断唤醒。

## 4. 调度器核心链表与变量

这些是 `tasks.c` 中的私有全局对象，不是新的 C 类型，但理解调度器必须掌握：

| 对象 | 含义 |
| --- | --- |
| `TCB_t * volatile pxCurrentTCB` | 当前运行任务 |
| `List_t pxReadyTasksLists[configMAX_PRIORITIES]` | 每个优先级一个就绪链表 |
| `xDelayedTaskList1/2` | 两个延时链表，分别容纳本轮 Tick 与回绕后的唤醒时间 |
| `pxDelayedTaskList` | 当前延时链表指针 |
| `pxOverflowDelayedTaskList` | 溢出延时链表指针；Tick 回绕时与当前链表交换 |
| `xPendingReadyList` | 调度器挂起期间由 ISR 唤醒、等待转入就绪态的任务 |
| `xSuspendedTaskList` | 显式挂起或无限期等待的任务 |
| `xTasksWaitingTermination` | 已删除、等待空闲任务释放内存的任务 |
| `uxCurrentNumberOfTasks` | 当前任务总数 |
| `xTickCount` | 系统 Tick 计数 |
| `uxTopReadyPriority` | 当前存在就绪任务的最高优先级信息 |
| `xNextTaskUnblockTime` | 最近一个延时任务的唤醒 Tick，用于快速判断 |
| `uxSchedulerSuspended` | 调度器挂起嵌套计数 |
| `xYieldPending` | 是否有一次上下文切换被延后 |

## 5. 队列结构（`queue.c`）

### 5.1 `Queue_t`

```c
typedef struct QueueDefinition
{
    int8_t *pcHead;
    int8_t *pcTail;
    int8_t *pcWriteTo;
    union {
        int8_t *pcReadFrom;
        UBaseType_t uxRecursiveCallCount;
    } u;
    List_t xTasksWaitingToSend;
    List_t xTasksWaitingToReceive;
    volatile UBaseType_t uxMessagesWaiting;
    UBaseType_t uxLength;
    UBaseType_t uxItemSize;
    volatile int8_t cRxLock;
    volatile int8_t cTxLock;
    /* 可选成员 */
} xQUEUE;

typedef xQUEUE Queue_t;
```

| 成员 | 含义 |
| --- | --- |
| `pcHead` | 存储区起始地址；信号量/互斥量没有实际数据区 |
| `pcTail` | 存储区末端标记 |
| `pcWriteTo` | 下一次写入位置 |
| `u.pcReadFrom` | 普通队列上一次读取位置，下一元素在其后 |
| `u.uxRecursiveCallCount` | 递归互斥量的重复获取次数，与读指针共用内存 |
| `xTasksWaitingToSend` | 因队列满而阻塞的任务事件链表 |
| `xTasksWaitingToReceive` | 因队列空而阻塞的任务事件链表 |
| `uxMessagesWaiting` | 当前已有元素数量；对信号量就是当前计数 |
| `uxLength` | 可容纳元素数；互斥量和二值信号量为 1 |
| `uxItemSize` | 每个元素字节数；信号量/互斥量为 0 |
| `cRxLock` / `cTxLock` | 队列锁定期间 ISR 收/发次数，解锁时统一处理任务唤醒 |
| `ucStaticallyAllocated` | 静态分配标记 |
| `pxQueueSetContainer` | 所属队列集 |
| `uxQueueNumber` / `ucQueueType` | 跟踪编号和对象类型 |

队列、二值信号量、计数信号量、互斥量和递归互斥量都使用此结构，通过 `uxItemSize`、队列类型及部分字段复用区分行为。

### 5.2 `QueueRegistryItem_t`

```c
typedef struct QUEUE_REGISTRY_ITEM
{
    const char *pcQueueName;
    QueueHandle_t xHandle;
} QueueRegistryItem_t;
```

当 `configQUEUE_REGISTRY_SIZE > 0` 时，内核维护此数组，使调试器能按名称找到队列或信号量；它不参与调度和同步。

## 6. 事件组结构（`event_groups.c`）

```c
typedef TickType_t EventBits_t;

typedef struct xEventGroupDefinition
{
    EventBits_t uxEventBits;
    List_t xTasksWaitingForBits;
    /* 可选：uxEventGroupNumber、ucStaticallyAllocated */
} EventGroup_t;
```

| 成员 | 含义 |
| --- | --- |
| `uxEventBits` | 当前事件位集合 |
| `xTasksWaitingForBits` | 等待事件位的任务链表；节点值同时编码等待位和控制标志 |
| `uxEventGroupNumber` | 跟踪编号 |
| `ucStaticallyAllocated` | 静态分配标记 |

本工程 `EventBits_t` 为 32 位，但最高 8 位用于 `eventCLEAR_EVENTS_ON_EXIT_BIT`、`eventUNBLOCKED_DUE_TO_BIT_SET`、`eventWAIT_FOR_ALL_BITS` 等控制标志，所以用户只能使用低 24 位。

## 7. 软件定时器结构（`timers.c`）

### 7.1 `Timer_t`

```c
typedef struct tmrTimerControl
{
    const char *pcTimerName;
    ListItem_t xTimerListItem;
    TickType_t xTimerPeriodInTicks;
    UBaseType_t uxAutoReload;
    void *pvTimerID;
    TimerCallbackFunction_t pxCallbackFunction;
    /* 可选：uxTimerNumber、ucStaticallyAllocated */
} xTIMER;

typedef xTIMER Timer_t;
```

| 成员 | 含义 |
| --- | --- |
| `pcTimerName` | 调试名称，内核不复制字符串内容 |
| `xTimerListItem` | 挂入当前或溢出活动定时器链表，节点值为到期 Tick |
| `xTimerPeriodInTicks` | 周期，必须大于 0 |
| `uxAutoReload` | `pdTRUE` 周期定时器，`pdFALSE` 单次定时器 |
| `pvTimerID` | 应用自定义标识，可让多个定时器共用一个回调 |
| `pxCallbackFunction` | 到期回调 |

### 7.2 定时器命令消息

```c
typedef struct tmrTimerParameters
{
    TickType_t xMessageValue;
    Timer_t *pxTimer;
} TimerParameter_t;

typedef struct tmrCallbackParameters
{
    PendedFunction_t pxCallbackFunction;
    void *pvParameter1;
    uint32_t ulParameter2;
} CallbackParameters_t;

typedef struct tmrTimerQueueMessage
{
    BaseType_t xMessageID;
    union {
        TimerParameter_t xTimerParameters;
        CallbackParameters_t xCallbackParameters;
    } u;
} DaemonTaskMessage_t;
```

`DaemonTaskMessage_t` 是定时器命令队列中的元素。`xMessageID` 区分启动、停止、复位、改周期、删除以及执行延迟回调等命令；联合体只保存该命令需要的一组参数。

| 成员 | 含义 |
| --- | --- |
| `pxCoRoutineFunction` | 协程入口 |

| `xEventListItem` | 队列事件等待节点 |

## 9. 内存管理结构（`portable.h`、`heap_*.c`）

### 9.1 `HeapRegion_t`

```c
typedef struct HeapRegion
{
    uint8_t *pucStartAddress;
    size_t xSizeInBytes;
} HeapRegion_t;
```

供 `heap_5` 描述多个不连续内存区。数组必须按起始地址升序排列，并以 `{ NULL, 0 }` 结束。

### 9.2 `BlockLink_t`

```c
typedef struct A_BLOCK_LINK
{
    struct A_BLOCK_LINK *pxNextFreeBlock;
    size_t xBlockSize;
} BlockLink_t;
```

`heap_2/4/5` 使用的内部空闲块头：`pxNextFreeBlock` 连接空闲链表，`xBlockSize` 保存块大小；`heap_4/5` 还借用最高位标记块是否已分配。块头按 `portBYTE_ALIGNMENT` 对齐并位于返回给用户的内存之前。

## 10. 静态分配占位类型（`FreeRTOS.h`）

| 类型 | 对应真实对象 | 用途 |
| --- | --- | --- |
| `StaticListItem_t` | `ListItem_t` | 静态链表节点占位 |
| `StaticMiniListItem_t` | `MiniListItem_t` | 静态哨兵占位 |
| `StaticList_t` | `List_t` | 静态链表占位 |
| `StaticTask_t` | `TCB_t` | `xTaskCreateStatic()` 的 TCB 缓冲区 |
| `StaticQueue_t` | `Queue_t` | 静态队列、信号量和互斥量控制块 |
| `StaticEventGroup_t` | `EventGroup_t` | 静态事件组控制块 |
| `StaticTimer_t` | `Timer_t` | 静态软件定时器控制块 |

这些结构通过 `void *`、基础类型数组和条件字段保证大小及对齐足以容纳真实内部对象。它们故意不暴露语义字段，防止应用代码依赖内核私有布局。

## 11. 数据结构之间的关系

```text
TaskHandle_t ──> TCB_t
                 ├─ xStateListItem ──> 就绪/延时/挂起/删除 List_t
                 └─ xEventListItem ──> Queue_t 或 EventGroup_t 的等待 List_t

QueueHandle_t ──> Queue_t
                  ├─ 环形数据存储区
                  ├─ xTasksWaitingToSend
                  └─ xTasksWaitingToReceive

EventGroupHandle_t ──> EventGroup_t ──> xTasksWaitingForBits

TimerHandle_t ──> Timer_t ── xTimerListItem ──> 当前/溢出定时器 List_t
```

最关键的设计是“对象拥有等待链表，任务拥有可插入链表的节点”。这样内核解除阻塞时，通过节点的 `pvOwner` 能以常数时间找回 `TCB_t`，再把任务移入对应优先级的就绪链表。

---

## 12. 当前配置对结构布局的影响

本工程当前开启任务通知，因此 `TCB_t` 包含 `ulNotifiedValue` 和 `ucNotifyState`；关闭互斥量、跟踪、应用任务标签和软件定时器，因此相关可选成员或对象不会编入当前固件。修改这些宏会改变内部结构大小，所有内核文件必须使用同一份 `FreeRTOSConfig.h` 重新完整编译。
